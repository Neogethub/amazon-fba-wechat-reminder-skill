# Codex 每日定时任务

使用 Codex 桌面应用提供的定时任务能力。Skill 定义执行流程，定时任务决定何时执行。客户电脑需在运行时开机、联网、保持唤醒且 Codex 保持运行；计划执行时间不代表手机会在该秒收到消息，读取 API 和推送需要时间。

## 统一提醒时区，适用于所有系统时区

当前版本统一在**北京时间每天09:00**提醒，对应 **UTC每天01:00**。电脑设置为中国、美国、欧洲或其他地区时，配置方法相同；不要要求用户改变电脑时区。使用客户端支持的明确UTC锚点或时区字段，不依赖电脑的本地时钟。在采用夏令时的地区，对应的本地时刻会变化，因此不能长期替换为某个固定本地小时，也不能将未指定时区的本地01:00误当UTC 01:00。

当前脚本的时间门槛、日期范围、每日去重和消息显示也统一使用北京时间。“每天9点”不代表每位用户各自当地9点。若用户需要其他提醒时区，应说明目前尚不支持该配置；仅改排程而未同步脚本的时区口径，会造成跳过或去重日期错误。

曾遇到客户端保存了 `Asia/Shanghai`，实际却将任务排到北京时间凌晨的情况。仅看到正确的时区名称或任务标题不足以确认成功；这属于已观察到的客户端行为，不代表每个版本都有相同问题。以**已保存任务实际计算出的下一次触发时间**为准。

## 创建或更新

1. 首次配置先验证一次真实 `preview` 和已授权的微信测试。仅修正已有排程时，复用仍有效的验证结果，不为改时区重复推送。测试失败时先解释具体失败，不宣称自动化已可用。
2. 运行 `configure.py schedule-info`，获取当前 Python 解释器和技能脚本的绝对路径、实际命令、数据目录，以及同一时刻的 `next_beijing_run` 和 `next_run_utc`。`scheduler_timezone` 为UTC、`scheduler_daily_time` 为01:00。这些是本地计算的目标，`scheduler_verified: false` 表示脚本没有查询已保存的任务。
3. 搜索可用的 `automation_update` 等 Codex 定时工具，阅读其当前参数。先查已有任务，更新同一用途的任务，避免新建重复任务。默认复用当前对话的定时任务；遵循工具当前支持的任务种类。
4. 优先通过定时工具配置UTC每天01:00，并使用 `next_run_utc` 作为明确的UTC起始时刻（若工具支持起始时间）。如工具支持独立时区字段，明确设为UTC；如仅支持本地时钟，不能直接填写01:00。遵循工具当前支持的设置方式；不通过修改数据库或绕过拒绝来强行保存。若需用户在界面完成操作，打开实际任务并说明缺少的设置，不臆测按钮名称。
5. 保存后回读同一任务的**启用状态、执行命令、数据目录及实际下一次触发时间**。优先使用工具返回值或应用界面；必要时只读客户端可用的本机排程元数据，不能把规则文本中写的时间当成实际计算结果。元数据位置随版本变化，不假设固定文件路径。
6. 将实际下一次触发时间换算成北京时间，核对日期和09:00附近的时刻。部分客户端会附加小幅错峰延迟，已观察到约0–2分钟，但不能将此范围当成所有版本的保证。如果出现凌晨或数小时偏差，继续修正；如果拿不到实际触发时间，明确标记“尚未核验”，不能只凭 `schedule-info` 或保存成功就报告定时正常。
7. 向客户报告核验后的具体日期、北京时间和任务状态。区分“排程已核对”“手动查询和推送成功”“首次自动触发已验证”：前两项不能替代最后一项，不保证微信09:00整送达。

仅生成建议卡、打印命令或脚本自身的9点门槛，都不代表排程已保存或启用。`scheduled` 在北京时间9点前退出码为0并跳过，是正常保护行为，**不是当天货件扫描和发送成功**；凌晨被误触发时也不会自动等到9点。

## 已安装用户升级

更新Skill文件不会自动更新已经保存的定时任务。升级后重新运行 `schedule-info`，找到原任务，保留其凭证来源、数据目录、收件人、业务规则和去重记录，通过定时工具修正排程，并按上面的步骤回读实际下一次触发时间。不要创建第二个同用途任务，也不要为了测试排程而删除当天发送记录或再次发送已接受的消息。

工具不可用时，提供任务名称、已解析命令和下面的任务文字供客户在应用里配置；明确本次尚未完成创建或更新，不推断已有任务的状态。用户只要求 Codex 任务时，不擅自改用系统服务或其他云端调度。

## 保存的任务文字示例

以下占位符应在创建任务前替换，不要将其原样保存：

> 每天北京时间09:00，使用已安装的 fba-shipment-reminder 技能，运行以下命令并等待完成：`<schedule-info 返回的实际命令>`。使用当前用户已配置的凭证及数据目录 `<实际数据目录>`，只读取近3个月创建的入库计划的未完成货件，按脚本中的48小时规则推送给已配置的本人微信，包括已过截止时间但未完成的货件。每票显示货件编号、仓库、最晚可编辑时间、当前送达窗口，统一为北京时间。缺少截止时间标记无法判断，无匹配货件也报告检查结果。只读亚马逊，不修改货件。遵守脚本去重，不删除发送记录；发送状态不确定时不要自动重发。检查退出状态，区分完成、跳过、运行冲突和失败；正常完成无需追加例行聊天消息，有异常或需要用户操作时再报告。不要输出凭证。

如使用 `FBA_REMINDER_HOME`，在任务中保存该环境变量的设置方式及绝对目录；不可把它误当多账号支持。不要将 Client Secret、Refresh Token、SendKey 或它们的值写入任务提示词。

若用户已经明确了时间、规则和接收人，沿用已给的授权，不重复询问。不同于定时推送的外部动作需另行依据用户请求判断。

参考：[OpenAI 官方定时任务说明](https://learn.chatgpt.com/docs/automations)。
